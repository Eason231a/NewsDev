# 黑马头条自媒体人管理系统 — 技术方案选型

> 版本 V1.0 | 2026-06-25 | 项目立项阶段

---

## 1. 项目背景

黑马头条是一款面向自媒体创作者的 **Admin Dashboard**，核心功能包括：图文内容管理、数据统计分析、素材管理、粉丝管理。前后端分离，单体应用起步。

**关键约束**：
- 团队技术栈以 Java + Vue 为主
- 需支持富文本编辑 + 图片上传
- 数据统计涉及多维度聚合查询
- 首版预计 5 个工作日交付

---

## 2. 总体架构

```
浏览器 ── SPA (Vue 3) ── HTTP/REST ── Spring Boot ── MySQL 8.0
                                          │
                                     阿里云 OSS (图片存储)
```

**决策：单体后端 + 单前端应用**

项目当前 15 张表、8 个业务模块，单体架构足够。过早微服务化会引入不必要的分布式复杂度（服务发现、分布式事务、链路追踪）。后续若业务量增长，可按业务域逐步拆分。

---

## 3. 后端选型

### 3.1 语言与框架

**选型：Java 17 + Spring Boot 3.2**

| 对比项 | Spring Boot 3.2 ✅ | Quarkus |
|--------|-------------------|---------|
| 生态成熟度 | 极高，插件/ Starter 丰富 | 成长中 |
| 团队熟悉度 | 主流培训体系，人员好招 | 较少团队使用 |
| 社区支持 | 问题秒搜到答案 | 文档相对薄弱 |

Spring Boot 对该项目没有短板，选最稳的。

### 3.2 ORM

**选型：MyBatis-Plus 3.5**

| 对比项 | MyBatis-Plus ✅ | Spring Data JPA |
|--------|----------------|-----------------|
| 复杂 SQL | 直接写 SQL，XML 维护 | JPQL/@Query，复杂场景吃力 |
| 动态筛选 | LambdaQueryWrapper 代码即条件 | Specification API，学习成本高 |
| 分页 | 内置插件，一行配置 | 自动处理但定制难 |
| 统计聚合 | SUM/AVG/JOIN 随心写 | 对象思维，聚合查询别扭 |

**决策理由**：本系统核心痛点是**数据统计**——按日期范围 SUM 阅读量/点赞数/转发数，LEFT JOIN 频道表做筛选，动态 WHERE 条件多达 5-6 个。MyBatis-Plus 让你直接控制 SQL，而不是和 ORM 较劲。

### 3.3 认证方案

**选型：无状态 JWT**

```
登录 → 返回 Token（24h 过期）→ 后续请求 Header 带 Authorization: Bearer <token>
```

| 对比项 | JWT ✅ | Session + Cookie |
|--------|-------|-----------------|
| 服务端状态 | 无状态，不占内存 | 需存 Session |
| 水平扩展 | 天然支持 | 需共享 Session（Redis） |
| 移动端兼容 | 通用 | Cookie 受限 |

**Token 设计**：
- 签名算法：HMAC-SHA256
- Payload：`{sub: userId, username, iat, exp}`
- 密钥通过环境变量 `${JWT_SECRET}` 注入，不写死在代码里

**用户隔离**：ThreadLocal 实现 `UserContext`，请求进入时解析 Token 设置 userId，Service 层所有查询必须带 `userId` 条件，防止越权。

### 3.4 依赖清单

| 依赖 | 用途 |
|------|------|
| spring-boot-starter-web | REST API + 内嵌 Tomcat |
| spring-boot-starter-security | BCrypt 密码加密（不用它的过滤器链） |
| spring-boot-starter-validation | 请求参数校验 |
| mybatis-plus-spring-boot3-starter | ORM + 分页 + 逻辑删除 |
| mysql-connector-j | 数据库驱动 |
| jjwt 0.12 | JWT 生成/解析 |
| hutool 5.8 | 通用工具（日期、文件校验） |
| springdoc-openapi 2.5 | Swagger UI 自动生成 |
| aliyun-sdk-oss 3.17 | 图片上传 OSS |
| lombok | 减少 getter/setter 样板代码 |
| H2 (test) | 测试环境内存数据库 |

### 3.5 不选的依赖

| 不选 | 理由 |
|------|------|
| Spring Security 过滤器链 | 只需要 BCrypt 加密，认证用 JWT Filter 自实现更轻量 |
| Redis | 首版 JWT 无状态，无需 Session 共享；统计数据实时查库，暂无缓存瓶颈 |
| XXL-Job | 首版暂无定时任务（统计数据先手工写入测试），后续需要再加 |

## 4. 前端选型

### 4.1 框架与语言

**选型：Vue 3 + TypeScript + Vite**

| 对比项 | Vue 3 ✅ | React |
|--------|---------|-------|
| 学习曲线 | 平缓，模板语法直观 | JSX 需适应 |
| UI 库配套 | Element Plus 原生 Vue 3 | Ant Design 偏 React |
| 中文生态 | 文档/社区/教程极丰富 | 英文为主 |
| 构建 | Vite（尤雨溪团队出品） | 可选方案多，选择成本高 |

**决策理由**：Admin Dashboard 场景 Vue + Element Plus 是中文圈最成熟方案，开发效率最高。

### 4.2 UI 组件库

**选型：Element Plus 2.x**

不做对比，Admin Dashboard 场景 Element Plus 是事实标准。Table/Form/Dialog/DatePicker/Pagination 全部开箱即用，本项目 90% 的 UI 需求它都覆盖。

### 4.3 富文本编辑器

**选型：Quill 2.0**

| 对比项 | Quill ✅ | TinyMCE | Tiptap |
|--------|---------|---------|--------|
| 包体积 | ~200KB | ~1MB | ~300KB |
| Vue 3 封装 | @vueup/vue-quill，开箱即用 | 需额外集成 | 完全自定义，工作量大 |
| 功能覆盖 | 加粗/斜体/标题/列表/图片 ✅ | 功能更多但本项目用不上 | 灵活但开发成本高 |

**决策理由**：本项目的编辑器需求是**常规排版 + 插入图片**，Quill 完全够用，体积还最小。不需要 TinyMCE 的高级功能（表格、公式、批注），也不需要 Tiptap 的完全自定义能力。

### 4.4 状态管理

**选型：Pinia 3.x**

Vue 官方推荐替代 Vuex。Setup 函数式写法，TypeScript 推导完美，没有 mutations 这个多余概念。本项目 2 个 Store（user、app）即可。

### 4.5 前端依赖清单

| 依赖 | 用途 |
|------|------|
| vue 3.5 | 框架 |
| typescript 6 | 类型安全 |
| vite 8 | 构建（HMR 毫秒级） |
| element-plus 2.14 | UI 组件 |
| pinia 3 | 状态管理 |
| vue-router 4 | 路由 + 导航守卫 |
| axios 1.18 | HTTP + 拦截器（JWT 注入、统一错误处理） |
| @vueup/vue-quill | 富文本编辑器 |
| dayjs 1.11 | 日期处理（2KB，moment.js 的 1/30） |
| sass | CSS 预处理 |

## 5. 数据库选型

**选型：MySQL 8.0**

| 对比项 | MySQL 8.0 ✅ | PostgreSQL |
|--------|------------|------------|
| 团队熟悉度 | Java 培训标配 | 较少接触 |
| 窗口函数 | 8.0 原生支持 | 原生支持 |
| JSON 类型 | 原生支持（content 字段） | 更强大但不必要 |
| 运维工具 | 生态最丰富 | 相对少 |

**核心设计决策**：

- **枚举用 TINYINT 而非 VARCHAR**：文章状态（0-5）、封面类型（0-2）等用数值，省空间且索引效率更高
- **软删除**：articles 和 materials 设 `deleted_at`，不物理删除，数据可恢复
- **统计数据独立表**：`article_stats_daily` 等与业务表分离，统计查询不影响业务写入

## 6. 文件存储选型

**选型：阿里云 OSS**

| 对比项 | 阿里云 OSS ✅ | 本地磁盘 |
|--------|-------------|---------|
| 可靠性 | 99.9999999999% 数据持久性 | 单机磁盘，故障即丢失 |
| CDN 加速 | 一键接入 | 需自建 |
| 备份 | 自动多副本 | 需自建备份策略 |
| 成本 | 按量付费，初期极低 | 看似零成本，故障代价高 |

上传路径规范：`materials/{userId}/{yyyyMMdd}/{UUID}.{ext}`，按用户隔离，按日期分区便于管理。

## 7. 关键架构决策

### 7.1 文章状态机

```
草稿 ──submit──▶ 待审核 ──approve──▶ 审核通过 ──publish──▶ 已上架
  ▲                 │                    ▲                  │
  │            reject                    │            unpublish
  │                 ▼                    │                  ▼
  └──edit── 审核失败            ┌───────┘            已下架
                                │
                         (重新 submit)
```

状态流转在 Service 层做白名单校验，非法流转直接抛 422。

### 7.2 API 设计规范

- 所有响应统一包裹：`{ code, message, data }`
- 分页统一格式：`{ list, total, page, pageSize }`
- 错误码遵循 HTTP 语义：400/401/403/404/413/422/500
- 参数校验用 `@Valid` + Jakarta Validation，不手写 if-else

### 7.3 安全底线

| 措施 | 实现 |
|------|------|
| 密码 | BCrypt 不可逆哈希 |
| Token | HMAC-SHA256 签名，24h 过期 |
| 越权防护 | 所有查询带 userId，不靠前端传参 |
| SQL 注入 | MyBatis `#{}` 参数化 |
| 文件上传 | 扩展名白名单 + 大小限制 2MB |

## 8. 未选型的预留项

以下能力首版不做，但架构上留好扩展点：

| 项目 | 当前状态 | 后续方案 |
|------|---------|---------|
| 图表库 | API 数据就绪，前端直接用 | ECharts（首版集成） |
| 缓存 | 实时查库 | Redis（统计热点数据） |
| 定时任务 | 统计数据手工录入 | XXL-Job 或 Spring Task |
| 消息通知 | 无 | RocketMQ（审核结果通知） |
| 容器化 | 本地开发 | Docker Compose → K8s |

## 9. 总结

| 层级 | 选型 | 一句话理由 |
|------|------|-----------|
| 后端框架 | Spring Boot 3.2 | 最稳的 Java 后端框架，没有之一 |
| ORM | MyBatis-Plus | 统计查询必须直接控制 SQL |
| 认证 | JWT | 无状态，前后端分离标配 |
| 数据库 | MySQL 8.0 | 团队最熟，够用 |
| 文件存储 | 阿里云 OSS | 云上图片存储首选 |
| 前端框架 | Vue 3 + TS + Vite | Admin Dashboard 开发效率第一 |
| UI 库 | Element Plus | 中后台场景事实标准 |
| 富文本 | Quill | 够用、够轻、Vue 3 集成好 |
| 状态管理 | Pinia | Vue 官方推荐，TS 友好 |

整体思路：**用最成熟的技术做最稳妥的交付，不过度设计，不提前优化。**
